# 实例运行监控台 页面说明

- 会话：# Camoufox 控制台 UI 功能设计
- 页面角色：子页面
- 导出时间：2026/7/29 22:52:59

【页面职责】
该页面为实例运行监控台，主要负责对本地或局域网中当前所有正在运行的 Camoufox 浏览器实例进行集中监控与管理。它为系统管理员或自动化操作员提供了全局系统资源（CPU和内存）的实时视图，并允许对各个活跃的浏览器进程进行置顶窗口、启动调试器、单体强杀以及全局一键停止等运维控制动作。

【业务对象】
一、浏览器运行实例
1. 系统进程 PID：操作系统分配给该浏览器实例的进程标识符。
2. 关联环境 ID：该运行实例所对应绑定的浏览器环境 Profile ID。
3. 实例名称：便于识别的用户自定义环境名称。
4. 运行模式与状态：包括有头渲染、无头模式、API 控制中，以及伴随资源异常时的无头警告状态。
5. 已运行持续时间：实例自启动以来的累计运行时间。
6. 本地 API 调试端点：以 WebSocket 协议暴露的 Playwright 调试地址，包含对应的 PID 路由。
7. 代理出口 IP 及地理位置：实例当前网络流量的出口 IP 地址及其所对应的国家与城市。
8. 内存占用：实例当前所消耗的物理内存估算值。
二、全局性能与配置指标
1. 全局最大并发数限制：系统允许同时运行的浏览器实例数量上限。
2. 系统 CPU 占用率：包含系统整体 CPU 占用、Firefox 进程占用的百分比以及物理 CPU 核心数。
3. 系统内存使用率：系统已用内存、总内存、浏览器缓存以及可用空间的具体数值。
4. 系统总进程数：当前正处于运行中状态的浏览器实例总数。
5. 本地接口服务状态：接口服务的运行状态及监听端口。
6. Camoufox 版本：当前全局 Active build 版本号。

【页面功能说明】
1. 系统资源实时监控：直观展示系统 CPU 和内存的波动状态与具体占用数据。
2. 全局最大并发数限制设置：提供滑块供用户动态调整允许同时运行的最大实例数量。
3. 全局一键停止：提供批量退出所有运行中实例的快捷手段。
4. 运行实例卡片墙：动态渲染当前活跃的浏览器实例列表，实时反映实例的状态、PID、运行时长、调试端点、出口 IP 和内存消耗情况。
5. 实例窗口控制与调试：支持对单个实例进行窗口置顶，或者唤醒 Playwright 官方 Inspector 进行脚本调试。
6. 实例强杀清理：支持对卡死或异常的实例进行强制停止以释放资源。
7. WebSocket 实时同步指示器：向用户明确当前数据是否正在通过 WebSocket 保持实时同步。

【关键用户动作与业务含义】
1. 调整全局最大并发数限制滑块：用户修改系统允许的最大并发数。业务含义是后端在接收到启动新环境的请求时，需校验当前运行实例数是否已达此上限，若达到则限制新环境的开启或进行排队处理。
2. 点击全部停止按钮：用户请求关闭所有运行中的浏览器。业务含义是后端需要向所有活跃的浏览器进程批量发送终止信号，强制杀掉进程并释放资源，同时更新这些实例的运行状态。
3. 点击置顶窗口按钮：用户希望将某个实例的浏览器界面聚焦显示。业务含义是后端需向对应 PID 的有头浏览器进程发送系统指令，将其窗口置于最前。此动作仅适用于有头渲染实例，无头模式下此操作被禁用。
4. 点击开启调试器按钮：用户需要对自动化脚本进行调试。业务含义是后端需要激活或连接至该实例的 Playwright 调试环境，打开 Inspector 界面。
5. 点击单个强制停止按钮：用户在实例卡死时执行的强杀动作。业务含义是后端向对应的 PID 进程发送强杀信号，彻底关闭进程，清除其内存占用，并向前端推送该实例退出的事件。
6. 点击返回环境列表按钮：用户切换工作上下文，跳转回环境列表主页面。

【数据与状态流转】
1. 监控建连与快照初始化：当用户进入此页面，前端会与后端建立 WebSocket 连接，后端首先向前端推送当前所有活跃实例的数据快照以及系统 CPU、内存等初始性能指标。
2. 状态实时推送：在连接建立期间，后端需监控系统资源以及浏览器进程的变化（例如新实例启动、进程因异常退出、内存占用突破预警阈值），并将这些事件通过 WebSocket 实时推送给前端，前端据此增删或更新卡片墙。
3. 实例运行状态机变化：实例启动后进入运行状态（细分为有头、无头或 API 控制中）。当用户或系统触发强杀或退出后，实例状态转为停止，并从当前运行卡片墙中移除。
4. 资源异常流转：当实例内存占用超过安全限度时，其实时状态会从普通的运行状态流转为带有高内存警告的异常状态，提示用户可能需要手动干预。

【异常与边界情况】
1. 内存占用异常：实例内存占用过高，后端需要能识别此类资源异常并向前端发送预警标记。
2. 无头渲染限制：对于处于无头模式运行的实例，置顶窗口动作属于无效操作。后端需确保接口控制或前端状态中对该动作进行禁用阻断。
3. 达到最大并发限制与安全阈值：当运行实例数达到设定的并发上限，或系统整体硬件占用触发安全阈值时，系统应自动限制新的环境开启。
4. 进程卡死与强杀失败：当实例无响应时，强杀接口（强制停止）必须具备较高的优先级和系统级执行权限，确保在常规退出机制失效时仍能彻底清除僵尸进程及其所占用的内存。
5. WebSocket 连接中断：如果前端与后端的实时连接异常断开，页面将无法获取最新的实例状态，后端需支持重连机制并在重连后重新同步最新的进程列表。

【对后端理解最重要的支撑点】
1. 实时进程监控与控制能力：后端不能仅仅依赖静态数据库，必须具备对操作系统本地进程（PID）的深度管理能力，能够实时获取进程级别的资源占用，并能向下执行系统级的进程调度与管理指令（如强杀、置顶）。
2. WebSocket 双向同步：页面的核心体验是“免刷新实时同步”，后端必须实现稳定、实时的 WebSocket 数据推送服务，将实例生命周期的变化和系统资源消耗无延迟地同步给前端。
3. 调试端口的管理与分发：后端启动浏览器实例时，必须为其正确配置并向前端返回相应的本地 WebSocket 调试端点，以便自动化脚本或调试器可以顺利连接到对应的进程。

【页面关系与流程承接】
1. 上游承接：当用户在环境管理页面中启动浏览器，或者通过本地 API 接口启动环境时，该实例的数据会立刻被推送到本页面并生成监控卡片。
2. 下游去向：用户可通过顶部的快捷工具按钮跳转回环境列表页，也可以通过侧边栏导航跳转到代理中心、指纹配置、本地 API 管理、系统设置等其他功能页面。环境实例被停止或强杀后，该实例会从本页面的卡片列表中消失，状态在环境管理列表中更新为未启动。
