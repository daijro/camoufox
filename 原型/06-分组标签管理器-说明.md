# 分组标签管理器 页面说明

- 会话：# Camoufox 控制台 UI 功能设计
- 页面角色：子页面
- 导出时间：2026/7/29 22:52:59

【页面职责】
该页面名为“分组标签管理器”，主要用于集中管理指纹浏览器“环境”（Profile）的分类与标记维度，即“分组”（Group）和“标签”（Tag）。其核心业务职责是为环境管理列表提供全局的筛选和分类依据。通过本页面，用户可以维护分组的层级结构（支持一级/二级树形结构）与标签的元数据（包含颜色与名称），从而在全局范围内对浏览器环境进行合理的资产归类和属性标记。

【业务对象】
一、 环境（Profile）：系统中的独立浏览器环境。本页面不直接编辑环境本身，但其关联的“分组”与“标签”在此管理，页面显示了各分类下环境的引用数量。
二、 分组（Group）：层级分类对象，采用树状结构，最大支持二级深度（一级分组和二级子分组），用于对环境进行物理隔离式的组织划分。一个环境只能归属于一个分组（或属于“未分类”）。
三、 标签（Tag）：多维度标记对象，扁平结构，包含标签名称与十六进制色值，用于对环境进行跨分组的特征标记。一个环境可以绑定多个标签。

【页面功能说明】
一、 分组架构管理树：展示当前系统内所有分组的层级关系及每个分组关联的环境数量。支持新增一级分组、在指定分组下新增二级子分组、重命名分组名称、删除分组。同时支持通过拖拽分组节点的手柄来跨级或同级调整排序和上下级属系。
二、 标签色彩中心：以表格形式展示系统中所有自定义标签的名称、代表色值代码、环境引用计数。
三、 标签快捷工具：支持输入新标签名称，通过快捷调色盘或自定义取色器选择颜色，快速创建新标签。
四、 标签维护操作：支持对单个标签进行重命名、修改色值代码、删除，并支持一键批量清理引用计数为0的无用标签。
五、 统计与返回：顶部展示全局“总分组数”和“标签分类数”两个指标摘要，并提供返回环境管理中心的快捷通道。

【关键用户动作与业务含义】
一、 新增一级/二级分组：创建新的环境组织分类。业务上需要在分组表新增记录，二级分组需要关联父分组ID。
二、 拖拽分组手柄：调整分组的树形结构归属或同级显示顺序。业务上意味着更改分组记录的父级ID（Parent ID）以及排序权重。
三、 删除分组：解除该分组与环境的关联并销毁分组。此操作会触发“防呆确认”，业务上必须遵循“保留环境”的安全机制，将关联环境的归属状态变更为系统默认的“未分类/未分组”。
四、 创建标签：新建一个环境分类标识。业务上需保存标签名称和与之绑定的十六进制色值，初始引用计数为0。
五、 修改标签颜色：为现有标签指定新的十六进制颜色代码，业务上需要全局同步该标签的色值。
六、 删除标签 / 立即清理：解除标签与环境的多对多映射关系，并物理删除该标签记录。
七、 清理0引用标签：系统扫描标签表，将所有引用计数为0的闲置标签记录进行批量清除，以保持数据库整洁。

【数据与状态流转】
一、 分组数据流转：创建分组时，向数据库写入分组记录（若为二级则记录 `parent_id`）。拖拽调整时，更新受影响分组的 `parent_id` 和排序字段。删除分组时，系统需首先将该分组（包括其包含的二级子分组）下所有环境的 `group_id` 清空（置为 `NULL` 或系统“未分组”ID），随后级联删除该分组及其二级子分组记录。
二、 标签数据流转：创建标签时，向数据库写入标签名称与色值。标签与环境为多对多关系（通过关联表实现）。当环境被贴上或移除标签时，关联表发生增删，该标签的“环境引用计数”随之递增或递减。当执行“立即清理”或“清理0引用标签”时，系统将删除关联表中对应的关系，并在标签主表中物理删除该标签数据。

【异常与边界情况】
一、 分组层级限制：分组架构仅支持一级和二级。在前端拖拽和后端接口处理中，需严格限制产生三级或更深层级的分组结构。
二、 命名唯一性：同一父级分组下不允许存在同名子分组；全局范围内不允许存在同名的标签（具体校验规则需后端配合，页面未体现是否允许全局分组重名）。
三、 删除有环境引用的分组：当用户尝试删除一个关联了环境（包含子分组中关联环境）的分组时，系统必须拦截并弹出防呆确认框。点击确认后，仅删除分组节点，被关联的数十个或数个环境的 `group_id` 必须安全地重置为未归属状态，绝不可级联删除环境。
四、 标签颜色修改：修改标签颜色时，必须支持自定义的任意 Hex 色值（如 #0d9488），需做格式合法性校验。

【对后端理解最重要的支撑点】
一、 数据的物理安全性：分组和标签均属于逻辑分类。无论是删除分组、删除标签，还是清理零引用标签，其底层的业务实体环境（Profile）以及对应的本地磁盘 Profile 目录（user_data_dir）都绝不能被物理删除，必须安全保留并移至未归类状态。
二、 树形结构设计：分组表需要支持树形结构设计（包含 `parent_id` 关系和排序值），后端需要提供用于处理拖拽排序和层级变更的批量更新接口。
三、 计数统计：标签的“环境引用计数”和分组的“环境数量”需要后端准确计算。在标签列表中，引用计数为 0 的标签在业务上被视为“无引用”或“废弃”，需支持基于引用数等于 0 的过滤与批量清理逻辑。

【页面关系与流程承接】
一、 上游入口：用户从“环境管理中心”的主列表页面点击相关入口，跳转进入此“分组标签管理器”页面（面包屑导航显示为环境管理中心之下的子页面）。
二、 下游去向：
1. 点击“返回环境管理”按钮，页面流程将退回至环境列表主页。
2. 在此页面上对分组名称、分组层级、分组顺序、标签名称、标签颜色作出的任何增删改操作，业务上都必须实时生效，并立即同步体现在环境管理主页的左侧筛选树、创建/编辑环境表单的分组下拉框、标签选择器，以及环境列表中的标签标签芯片上。
