# 环境详情控制台 页面说明

- 会话：# Camoufox 控制台 UI 功能设计
- 页面角色：子页面
- 导出时间：2026/7/29 22:52:59

【页面职责】
该页面用于展示并精细化管理单个独立指纹浏览器环境（Profile）的全部配置、运行状态及本地物理数据。它是用户对浏览器环境进行深度调试与控制的控制中心，支持实时进程交互控制、物理文件级别的安全清理、网络代理的检测与更换、Cookie 凭证的直接导入/导出与编辑，以及实例运行历史日志的审计。

【业务对象】
1. 环境（Profile）：核心业务对象，承载指纹浏览器的配置参数与本地数据存储目录。
2. 浏览器实例（Browser Instance）：环境中正在运行的物理进程，与操作系统 PID 绑定。
3. 代理配置（Proxy）：环境绑定的网络链路凭证，包含协议、地址、端口及身份校验信息。
4. Cookie 凭证：环境中缓存的网站登录会话数据，以 JSON 格式存储与解析。
5. 运行日志（Runtime Log）：记录该浏览器环境生命周期中启动、关闭、配置加载及代理异常等系统事件的记录。

【页面功能说明】
1. 顶部状态与进程控制栏：展示当前环境的生命周期状态（运行中/空闲）及物理进程 PID。提供“聚焦窗口”（使当前运行的浏览器窗口获取系统焦点）和“强制停止”（杀死浏览器进程）的快捷操作。
2. 配置分类导航：左侧栏提供快速锚点，并直观展示当前环境对应的本地磁盘物理数据目录的绝对路径以及占用的磁盘空间大小。
3. 基本信息与启动配置模块：展示指纹策略与配置哈希（只读）。提供物理数据控制动作，包括「清除缓存但保留 Cookie」与「重置 Profile 目录」。支持修改启动运行模式（有头/无头）、启动分辨率以及默认启动 URL。Camoufox 版本为全局 Active，不在环境级别配置。
4. 代理与地理网络模块：展示当前绑定代理的协议、IP、端口、账密和根据出口 IP 自动推导的地理位置及IANA时区。展示最近的代理出口连通历史记录（时间、出口IP、时区、延迟、状态）。支持通过弹窗“更换代理配置”。
5. Cookie 与凭证管理模块：展示当前浏览器环境中的 Cookie 详情（支持在线直接编辑 JSON），提供清空、导出 JSON 文件以及导入并解析保存的操作，并能展示格式校验结果（如有效记录条数）。
6. 运行日志模块：展示最近 50 次该环境的启动、指纹伪装应用、正常关闭或代理连接超时等日志流，提供下载完整日志流的入口。
7. 危险操作区：提供将环境逻辑删除移入回收站的动作。
8. 更换代理弹窗：支持用户手动输入新的代理协议与网络信息，或从已有的代理库中选择，并在保存前提供连通性测试。

【关键用户动作与业务含义】
1. 强制停止：后端需向操作系统发送终止进程指令（kill），强行收回由于网络挂起或异常卡死的浏览器实例，更新状态为空闲。
2. 清除缓存并保留 Cookie：后端需定位到该环境的物理 Profile 路径，物理删除除 Cookie 数据库以外的缓存和临时文件。
3. 重置 Profile 目录：后端需物理清空该 Profile 目录下的所有浏览器生成数据，将其还原至首次创建状态，但保留指纹配置元数据。
4. 更换并保存代理配置：解绑环境原有的代理关系，关联并应用新代理，若环境处于运行中，此操作应在下一次启动时生效（或在保存时更新运行配置）。
5. 测试代理连接：后端根据输入的代理参数，临时通过该代理向特定服务发起请求，计算延迟并返回最新的出口 IP、国家与时区信息。
6. 导入并解析 Cookie：用户提交新的 JSON，后端需在写入物理 Cookie 文件前，对 JSON 结构进行格式校验与反序列化，确保 domain、name、value 等关键字段无畸变。
7. 将该环境扔进回收站：逻辑删除，在数据库中标记删除时间，使其在主列表中隐藏。

【数据与状态流转】
1. 运行状态流转：环境默认处于“未启动”（空闲）状态；用户启动后变为“运行中”，并绑定后端返回的进程 PID；发生“强制停止”或网络超时崩溃时，状态流回“未启动”，并解绑 PID。
2. 代理测试状态流转：更换代理时，连接测试状态从“未执行”进入“检测中”，后端返回成功则更新检测历史并标绿“正常”，超时或连接失败则标红“失败”。
3. 删除状态流转：活动环境触发“扔进回收站”后，进入逻辑删除状态，等待回收站的彻底清理或恢复操作。

【异常与边界情况】
1. 进程杀死失败：当执行“强制停止”但操作系统进程未响应时，后端需设计重试或强杀机制，防止前端状态显示为空闲但本地句柄仍被占用的冲突。
2. Cookie 编辑格式错误：当用户在 TextArea 中直接修改 JSON 产生语法错误时，后端保存接口需拦截并返回校验失败，阻止写入本地存储防止浏览器损坏。
3. 代理连接超时：若浏览器启动后代理失效，底层抛出 SOCKS5 校验或连接超时（如日志中所示），后端需捕获此事件，主动向前端推送实例崩溃告警并终止进程。
4. 物理文件缺失：用户触发清除缓存或重置时，若物理 Profile 目录被用户在操作系统中手动删除，后端应有创建新空目录的容错保护。

【对后端理解最重要的支撑点】
1. 进程和磁盘目录生命周期管理是后端的核心职责。后端不能仅做 SQLite 数据的 CRUD，必须具备对系统本地进程（PID）的监控、对物理文件夹（Profile 路径）大小的动态计算、以及物理文件的删除与覆盖写入能力。
2. 日志模块需要后端收集底层 Camoufox 引擎抛出的事件（例如加载指纹、代理连接异常 SOCKS5 Timeout 等），并将其格式化持久化到日志表中，供前端以 Timeline 形式拉取。
3. 代理管理包含 GeoIP 推导，后端在测试代理或保存代理时，需根据代理 IP 推导出正确的国家和时区，作为后续 Camoufox 启动时注入 C++ 层的指纹配置参数。

【页面关系与流程承接】
1. 承接来源：用户从“环境管理列表页”（/profiles）点击编辑某个环境，路由至此详情页。
2. 路由跳转：面包屑“环境管理”点击可跳回列表页；侧边栏可跳往“实例监控”、“代理中心”、“指纹配置”等其他一级模块。
3. 数据依赖：更换代理弹窗中「从代理库中选择」需调用代理中心接口；指纹信息为只读摘要，高级编辑跳转指纹策略模板中心。
