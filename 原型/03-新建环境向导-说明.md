# 新建环境向导 页面说明

- 会话：# Camoufox 控制台 UI 功能设计
- 页面角色：子页面
- 导出时间：2026/7/29 22:52:59

【页面职责】
该页面用于用户在本地或局域网中创建并配置一个新的独立的防关联浏览器环境（Profile）。该向导提供了基础信息录入、网络代理绑定、指纹策略选择，以及账户历史 Cookie 导入的配置流程，最终可将配置保存至本地数据库（SQLite）中，并可选择是否在保存后立即拉起对应的浏览器实例。

【业务对象】
1. 环境 (Profile)：核心管理对象，包含名称、用途分类、备注、本地物理路径等元数据。
2. 代理 (Proxy)：网络出口配置，可以即时新建绑定，也可以从已有代理中心库中选择，或采用直连模式。
3. 指纹策略 (Fingerprint Strategy)：Camoufox 启动时的指纹生成方式（自动随机 / 真实预设采样 / 已保存模板），非手填 UA。
4. 分组 (Group)：环境的分组归属关系。
5. 标签 (Tag)：环境的多标签分类标记。
6. Cookie (凭证数据)：用于免密登录的目标网站会话凭证，格式为 JSON 数组。

【页面功能说明】
1. 基础信息管理：配置环境的名称、用途平台（如 Facebook、Amazon 等）、关联已有的分组或在页面内快捷创建新分组、配置多个自定义标签以及录入备注。
2. 代理路由配置：支持直连、从代理库选择或即时新建代理三种模式。新建代理模式下支持录入协议类型（SOCKS5/HTTP/HTTPS）、主机 IP、端口及认证凭据，并提供连通性检测，成功后会显示出口 IP 和国家、时区等地理信息。
3. 指纹策略配置：三选一 radio 卡片——自动随机生成（BrowserForge，默认）、从真实设备预设采样（fingerprint_preset）、使用已保存模板（固定 seed）。默认可见 OS 选择与「启动时根据代理自动对齐时区/语言/WebRTC」开关。高级参数（分辨率、WebRTC 策略）默认折叠。
4. 凭据导入：提供大文本框，支持用户直接粘贴 JSON 数组格式的 Cookie 凭据。
5. 指纹策略摘要：右侧预览卡片展示当前策略、OS、代理 Geo 对齐状态，提示「启动时由 Camoufox 自动生成完整指纹」。

【关键用户动作与业务含义】
1. 新建分组：在不离开当前页面的情况下，向分组管理中心快速插入一条新的分组数据。
2. 测试代理连通性：触发后端通过配置的代理通道访问公网，验证代理可用性，并反查代理的出口 IP、物理地区和所属时区。
3. 选择指纹策略：映射为 Camoufox 启动参数 `generate_fingerprint()` / `fingerprint_preset=True` / 固定模板 JSON。
4. 保存并立即启动环境：将所有配置写入 SQLite，并调用 Camoufox 在本地拉起 Firefox 浏览器实例。
5. 仅保存至环境列表：仅将配置写入数据库，将该环境状态置为闲置（Idle），不拉起浏览器。

【数据与状态流转】
1. 输入流向：前端提交表单数据 -> 后端进行参数校验（如 Cookie JSON 有效性） -> 写入本地数据库，同时创建对应的独立 Profile 物理目录。
2. 代理数据联动流：代理连通性测试返回的国家、时区等信息，作为 `geoip=True` 的实际注入参数，在启动浏览器时写入 `CAMOU_CONFIG`。
3. 状态流转：
   - 仅保存：环境被持久化，初始状态为「未启动」（Idle）。
   - 保存并启动：环境被持久化 -> 调用 Camoufox 启动接口 -> 实例监控模块中状态变为「运行中」（Running）。

【异常与边界情况】
1. 代理连通性异常：在测试代理或启动环境时，若代理网络断开、超时或认证失败，后端应向前端返回具体的网络错误码和异常原因。
2. Cookie 格式异常：用户输入的 Cookie 不是合法的 JSON 数组结构，后端需在保存前进行格式校验，解析失败时应拒绝保存并返回错误提示。
3. 命名或 IP 冲突：环境名称重复或绑定的新建代理信息已存在，后端需做排重校验。

【对后端理解最重要的支撑点】
1. 时区与经纬度跟随：测试代理成功后返回的地理信息非常关键，Camoufox 启动时需将代理 Geo 参数注入 C++ 层（`CAMOU_CONFIG`），对应 `geoip=True`。
2. Cookie 安全：Cookie 由用户粘贴导入，后端存储时加密保存，启动时解密并通过 Playwright `add_cookies()` 注入。
3. 启动参数组装：指纹策略映射为 Camoufox `launch_options()` 参数，UA/Canvas/WebGL 等由 BrowserForge 自动生成，无需用户手填。

【页面关系与流程承接】
1. 入口：通常由「环境管理（环境列表页）」的「新建环境」或「/profiles/new」路由进入。
2. 放弃流向：点击「放弃配置」返回，会放弃当前表单中未保存的所有内存数据，并退回到环境管理主页面。
3. 成功流向：保存成功后重定向返回「环境列表页」；若选择「保存并立即启动」，则除了落库和重定向，后端还需在后台拉起物理浏览器窗口，并在「实例监控」中注册该实例。
