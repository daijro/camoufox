# 环境回收站 页面说明

- 会话：# Camoufox 控制台 UI 功能设计
- 页面角色：子页面
- 导出时间：2026/7/29 22:52:59

【页面职责】
该页面作为环境管理模块的二级功能页，承担已删除浏览器环境（Profile）的暂存与安全保护职责。它用于防止用户因误删除而丢失绑定的账号或 Cookie 等敏感数据，允许用户在此页面对已逻辑删除的环境进行一键恢复，或者在确认安全的前提下对本地配置文件进行彻底的物理销毁，释放磁盘空间。

【业务对象】
1. 已废弃环境（Profile）：已被逻辑删除但保留在本地磁盘的环境实体。包含环境名称、环境备注、原属分组、删除时间等属性。
2. 浏览器配置文件目录（user_data_dir）：本地存储环境指纹、Cookie、缓存等数据的物理文件夹，具有具体的文件路径及磁盘占用大小。
3. 回收站状态信息：包含逻辑删除总数、今日新增数、最快到期的自动销毁剩余时间以及可释放的物理磁盘空间总量。

【页面功能说明】
1. 数据安全保护期看板：展示回收站当前的待清理环境总数、逻辑删除占用的物理磁盘空间总量、今日新增待办数、最快到期的环境数量及倒计时，以及历史已安全恢复的累计数量和恢复率。
2. 已废弃环境列表展示：以表格形式分页展示已逻辑删除的环境，提供名称、备注、绑定代理标识、原属分组、删除时间、存储路径及大小、自动销毁倒计时等元数据。
3. 搜索过滤：支持用户输入环境名、备注来模糊检索回收站中的特定环境。
4. 批量操作：支持勾选多个环境执行批量恢复，以及一键清空回收站的所有环境。
5. 单个环境控制：提供单个环境的“恢复”操作和“彻底删除”入口。
6. 安全防呆销毁弹窗：点击彻底删除或一键清空时触发，强制用户必须选择一种销毁执行策略（策略A：仅从控制台列表/数据库擦除记录，保留本地物理文件；策略B：彻底物理删除配置及本地所有指纹数据文件夹）。

【关键用户动作与业务含义】
1. 输入搜索词：用户检索特定的已废弃环境，后端需对已被逻辑删除的数据进行模糊匹配检索。
2. 点击“恢复”（单条或批量）：触发恢复逻辑，业务含义是将环境状态从逻辑删除中还原，重新回流到正常的环境列表，恢复其可用性。
3. 点击“彻底删除”/“一键清空回收站”：触发销毁流程，系统必须弹出高危操作确认对话框。
4. 勾选销毁执行方式（必选复选框）：用户明确指定数据清理粒度，这决定了后端的底层删除行为。
5. 确认执行销毁：向后端提交最终销毁指令，后端根据用户选定的策略执行数据库记录清除或物理目录擦除。

【数据与状态流转】
1. 状态改变：
   - 环境移入回收站后，状态变更为已逻辑删除，并记录“删除时间”，开始计算自动销毁倒计时。
   - 触发“恢复”后，环境状态流转回激活状态，从回收站列表中移除，重回环境管理主表。
   - 触发“确认执行销毁”（且选择了物理擦除）后，环境的元数据被彻底删除，对应的物理目录被擦除，生命周期终结。
2. 数据依赖：
   - 自动销毁倒计时需要后端根据系统的保护期规则（例如30天）结合删除时间实时计算并返回给前端。
   - 存储空间大小（如 420.5 MB）以及路径信息需后端定期扫描或实时统计对应的本地文件夹得出。

【异常与边界情况】
1. 销毁策略校验未通过：用户在确认弹窗中未勾选任何一种“销毁执行方式”时，前端应拦截提交，后端也应在接收到空策略请求时返回错误提示。
2. 物理文件占用异常：当后端尝试物理删除本地 user_data_dir 目录时，若该环境对应的浏览器进程尚未完全退出或文件被系统占用，后端需处理文件锁异常并向前端返回删除失败的具体原因。
3. 并发操作冲突：在自动销毁临界点，若用户刚好点击“恢复”，需要后端在事务中保证操作原子性，避免出现恢复成功但文件已被定时任务销毁的脏数据。
4. 批量操作空校验：用户未勾选任何记录时点击批量恢复，系统应限制或拦截请求。

【对后端理解最重要的支撑点】
后端开发必须明确，彻底删除绝不仅仅是数据库执行一条 DELETE 语句，它是一个高危的本地 I/O 操作。后端必须根据前端传来的 destroy_policy 决定是否调用系统底层接口去清空本地磁盘的 user_data_dir 目录。物理空间统计（如“可释放磁盘空间 2.4 GB”）是控制台的重要业务指标，后端需支持对已删除环境本地目录体积的累加计算。同时，自动销毁倒计时暗示后端需要有一个定时清理的后台任务（如 Cron 任务）来定时扫描已过保护期的逻辑删除数据并进行物理销毁。

【页面关系与流程承接】
1. 入口：用户在环境管理主页面将环境删除后，数据逻辑上流入本页面；用户也可以直接通过侧边栏导航切换至“环境回收站”。
2. 出口：执行“恢复”操作后，数据流回到环境管理列表；执行“彻底删除”后，数据完全销毁，不再流向任何页面。
